Integrations

If your users log into it, we can protect and govern it

Four integration paths cover the whole estate: standard federation protocols, a Python connector framework for anything with an interface, browser-plugin SSO for legacy logins, and ticketing workflows for systems without APIs.

Directories & identity sources

Authoritative sources that drive authentication and lifecycle events.

IamLogic reads users and groups from your directory, so people sign in with the accounts they already have. HR systems and other authoritative sources connect through the Python connector framework and drive joiner, mover and leaver events in IamLogic IGA.

  • Microsoft Active Directory
  • Microsoft Entra ID (Azure AD)
  • OpenLDAP
  • Google Workspace Directory
  • HRMS platforms (via connector framework)
  • Databases & CSV/API feeds

Business applications

SSO via SAML/OIDC/OAuth2 and provisioning via connectors.

Applications that support SAML, OpenID Connect or OAuth2 sign in through Access Manager single sign-on. For provisioning, IamLogic IGA creates, changes and removes accounts in connected applications through their connectors.

  • Microsoft 365
  • Google Workspace
  • Salesforce
  • SAP applications
  • Zoho suite
  • Tally & finance systems
  • Atlassian (Jira, Confluence)
  • Custom web applications

Infrastructure & network

Authentication for the layers beneath your applications.

VPN gateways and network devices send sign-in requests to the IamLogic RADIUS server, which adds multi-factor authentication without changing the device itself.

  • VPN gateways (RADIUS MFA)
  • Network devices (RADIUS)
  • Linux servers
  • Windows servers
  • Apache Guacamole
  • Cloud consoles (AWS, Azure, GCP)

ITSM & ticketing

Provisioning workflows for applications without APIs, and request integration.

For applications without an API, IamLogic IGA raises a ticket in ServiceNow or Zoho Desk for each access change. A person makes the change, and IGA tracks the ticket through to completion, so the change stays part of your governance records.

  • ServiceNow
  • Zoho Desk
  • Custom ITSM (via connector framework)

Legacy applications

Browser-plugin SSO with credential auto-fill, plus optional password rotation after every use.

The IamLogic browser plugin signs users in to legacy web applications by filling in the application's own login form, so users never need to know the password. Access Manager stores the credentials encrypted. Where password rotation is switched on for an application, Access Manager's rotation service changes the password automatically after every use, so a copied password soon stops working. Rotation is set up for each application.

  • Legacy web applications (any login form)
  • Core business systems without federation
  • Vendor portals
  • Intranet applications

Access Manager + IGA

How the two products connect

Access Manager and IamLogic IGA are built to work together. IGA users sign in through Access Manager single sign-on, and IGA manages Access Manager users and groups through a built-in connector.

FAQ

Common questions

What if an application has no API?

There are two routes. For account changes, IamLogic IGA can use a ticketing workflow: a ticket is raised in ServiceNow or Zoho Desk, a person makes the change, and IGA tracks the ticket through to completion. For sign-in, if the application has a web login page, the browser plugin can bring it under single sign-on and MFA without changing the application.

Can we build our own connectors?

Yes. The connector framework is written in Python, so your team or ours can build connectors for home-grown systems and anything else with an interface. Our services team also builds, documents and maintains custom connectors.
